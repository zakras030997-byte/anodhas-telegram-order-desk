# Заказы из Telegram

Нативная программа для macOS от ANODHAS AI: подключите собственного Telegram-бота, получайте заявки, проверяйте позиции и собирайте сводку на день.

## Как пользоваться

1. Создайте отдельного бота через [официальный BotFather](https://t.me/BotFather).
2. Откройте приложение, вставьте токен в защищённое поле и нажмите «Подключить». Токен сохраняется в Связке ключей macOS.
3. Клиент открывает вашего бота и отправляет заказ личным сообщением. Программа должна оставаться открытой, Mac — включённым и подключённым к интернету.
4. Выберите заявку, проверьте исходник и поля. Исправьте дату, позиции, количество, единицы и доставку. При необходимости отправьте подготовленные вопросы отдельной кнопкой после просмотра.
5. Подтвердите заказ. Он попадёт в сводку выбранного дня и экспорт CSV.

Для знакомства без токена нажмите «Демо-пример». Это локальные демонстрационные образцы.

## Пример сообщения

```text
На завтра 3 пачки кофе Арабика 1 кг и две бутылки сиропа ванильного 1 л.
Самовывоз
```

Также поддерживается «кофе Арабика 1 кг 2 пачки», дата ДД.ММ.ГГГГ, десятичное количество, слова один–десять и строка `Адрес: ...`.

Разбор выполняется локальными правилами. Сложная речь, опечатки, голосовые и изображения без подписи автоматически не разбираются. Неизвестные поля остаются пустыми для оператора. Отмены и изменения сохраняются отдельной заявкой и не меняют старые заказы автоматически. Ответ на уточнение также появляется отдельной записью; связывает его с заказом оператор.

## Подключение и данные

- Прямой [Telegram Bot API](https://core.telegram.org/bots/api): `getMe`, `getWebhookInfo`, `getUpdates`, `sendMessage`. Сервер и платная модель не нужны.
- Подключается один бот одновременно; его сохранённые сообщения имеют собственные идентификаторы источника. При смене бота прежние заявки остаются в общем списке, сводка охватывает все подтверждённые заявки за дату.
- Если у бота уже настроен webhook, программа останавливается и ничего не отключает. Два приложения не должны одновременно получать сообщения одного бота.
- При ошибке сети получение повторяется через 10 секунд, при 429 учитывается `retry_after`. Конфликт 409 останавливает получение.
- Telegram хранит необработанные события [не более 24 часов](https://core.telegram.org/bots/api#getting-updates). Это не загрузчик всей истории Telegram. Переписка личного аккаунта не читается.
- Заказы и следующий offset записываются атомарно в JSON в sandbox-контейнере приложения. Дубликаты сообщений подавляются. При повреждённом файле или ошибке диска получение блокируется.
- Токен не входит в JSON, CSV и журналы. Его можно удалить через меню «Ещё». Закрытие программы прекращает получение; автозапуска и фонового сервера нет.
- Входящие сообщения не исполняются. Внешние URL и команды из них не запускаются. Исходящие уточнения — только по действию оператора; неизвестный результат отправки автоматически не повторяется.
- Сводка суммирует только подтверждённые полные заявки и полностью совпадающие названия с единицами. CSV экранирует формулы в текстовых ячейках. Данные заказов остаются на Mac, текст уточнения передаётся выбранному клиенту через Telegram.

## Сборка

Требуются macOS 13+, инструменты командной строки Apple и совместимые Swift/SDK. Сторонних зависимостей нет.

```sh
bash Scripts/build.sh
bash Scripts/package.sh
```

Скрипт сборки собирает Universal `arm64 + x86_64`, создаёт и проверяет приложение. Упаковка создаёт DMG с инструкцией и ссылкой «Программы».

Для явного SDK: `ORDER_DESK_SDK=/путь/к/MacOSX.sdk bash Scripts/build.sh`. Для Developer ID задайте `SIGN_IDENTITY`; нотарификация — отдельный шаг владельца сертификата. При отсутствии идентификатора используется локальная ad-hoc подпись: macOS на другом компьютере может блокировать запуск. Скрипты не обходят Gatekeeper и не удаляют карантин.
